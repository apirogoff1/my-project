# RULES.md - Правила разработки проекта

## Стек технологий
- Next.js 15 (App Router)
- React 19, TypeScript 5 (строгий режим, без any)
- Tailwind CSS 3, shadcn/ui, Framer Motion
- Zustand (состояние), TanStack Query (запросы к API)
- React Hook Form + Zod (формы и валидация)
- Prisma 5 + PostgreSQL 17
- AI: Groq llama-3.3-70b-versatile через ai SDK v6

## Структура папок
- app/         — страницы и роуты Next.js (App Router)
- features/    — фичи: auth, ai-chat, payment и т.д.
- shared/      — утилиты, константы, типы, lib/
- entities/    — бизнес-сущности (User, Product и т.д.)
- widgets/     — крупные блоки страниц
- hooks/       — кастомные React хуки
- store/       — Zustand сторы
- components/  — общие UI компоненты

## Правила кода
- Всегда TypeScript, никогда any
- Компоненты только функциональные
- Стили только через Tailwind CSS
- Валидация только через Zod
- Формы только через React Hook Form
- Запросы к API только через TanStack Query
- Состояние только через Zustand
- Анимации только через Framer Motion

## Server vs Client компоненты
- По умолчанию все компоненты — Server Components
- "use client" только если используешь: useState, useEffect, onClick, анимации
- Никогда не делай весь layout клиентским

## Именование файлов и папок
- Компоненты: PascalCase (UserCard.tsx)
- Хуки: camelCase с префиксом use (useAuth.ts)
- Сторы: camelCase с суффиксом Store (authStore.ts)
- Утилиты: camelCase (formatDate.ts)
- Папки: kebab-case (user-profile/)

## Обработка ошибок
- Всегда оборачивай запросы в try/catch
- Всегда возвращай понятные сообщения об ошибках пользователю
- Используй error.tsx и not-found.tsx в каждом роуте
- Логируй ошибки на сервере

## Переменные окружения
- Все секреты только в .env (или .env.local)
- Публичные переменные с префиксом NEXT_PUBLIC_
- Никогда не коммить .env в git
- Всегда валидируй env-переменные через Zod при старте

## Безопасность
- Всегда валидируй данные на сервере, даже если валидировал на клиенте
- Никогда не доверяй данным от пользователя
- Все Server Actions защищать проверкой авторизации
- Чувствительные данные никогда не передавать на клиент
- Перед продакшном запустить: npm audit

## Правила для AI-агентов
- Всегда следуй структуре папок
- Всегда добавляй TypeScript типы
- Всегда валидируй данные через Zod
- Пиши компоненты максимально переиспользуемыми
- Комментарии на русском языке
- Не изменяй существующие API контракты без явного запроса
- Не добавляй новые зависимости без явного запроса
